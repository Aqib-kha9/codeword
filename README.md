# SafeText — 1-Tap Encrypt & Decrypt (Next.js PWA)

The simplest possible way to encrypt/decrypt text on your phone. **Everything
runs locally in the browser** — there is no backend, no analytics, and your
text/password never leave your device.

## How simple is it?

Just **two steps**:

1. Paste (or type) your text and enter your password.
2. Press **Encrypt & Copy** or **Decrypt & Copy**.

That's it. There are two clear buttons — you choose whether to encrypt or
decrypt. The result is **copied to your clipboard automatically**, so you can
paste it straight into any chat (WhatsApp, Telegram, Instagram, SMS…).

### Extra conveniences

- Two separate **Encrypt** and **Decrypt** buttons — no ambiguity.
- 🔑 **Remembers your password** (optional checkbox) — type it once, forget it.
  Stored only in your own browser, never sent anywhere.
- ✨ **Auto-focus** on the text box when you open the app.
- 📱 **Installable PWA** — use "Add to Home Screen" and it opens like a real app
  (works on both Android and iPhone).

## Security details

| Property | Value |
| --- | --- |
| Cipher | AES-256-GCM (authenticated encryption) |
| Key derivation | PBKDF2, SHA-256, **250,000** iterations |
| Salt | Random 16 bytes per message |
| IV / nonce | Random 12 bytes per message |
| Output format | `ENC1:` + base64(salt ‖ iv ‖ ciphertext ‖ auth tag) |

- A **fresh random salt and IV** are generated for every message, so encrypting
  the same text twice produces different output.
- GCM provides **integrity + authenticity**, so tampered text is rejected.
- Wrong password → decryption fails cleanly (no partial/garbage output).
- The password is **never stored**. If you lose it, the data is unrecoverable by
  design.

> ⚠️ This app protects text **in transit/storage as ciphertext strings**. Because
> all processing is client-side, hosting it on any static host keeps zero
> knowledge of your data.

## Getting started

```bash
npm install
npm run dev
```

Open http://localhost:3000 in your browser.

To create an optimised production build:

```bash
npm run build
```

Because the app now uses `output: "export"` (needed for the Android wrapper),
`npm run build` produces a fully static site in the `out/` folder. Serve it with
any static server, e.g.:

```bash
npx serve out
```

## Regenerating the app icons (optional)

The icons in `public/icons/` are generated by a dependency-free script:

```bash
node scripts/generate-icons.js
```

## Android app + floating bubble (optional)

The web app works as a normal PWA, but a website **cannot** show a bubble on
top of other apps. To get a real "side icon that stays even after the app is
closed", the project is wrapped with **Capacitor** and ships a small native
Android plugin (`FloatingBubble`) that runs a foreground service and draws a
draggable lock bubble with `WindowManager`.

What you get on Android:

- Tap **"Floating taala chalu kar"** inside the app.
- Allow **"Display over other apps"** (and notifications on Android 13+).
- A small teal lock bubble appears on the edge of the screen.
- **Close the app** — the bubble stays, floating over your home screen and
  other apps. Tap it to reopen SafeText.
- Drag the bubble anywhere with your finger.
- Turn it off again from the same button in the app.

> ℹ️ This is **Android only**. iOS does not allow apps to draw persistent
> overlays on top of other apps, so there the bubble is simply hidden.

### Building the Android app

Requirements: Android Studio (with the Android SDK) and Node. The Android build
(Gradle) must run on your machine — it downloads Gradle + the Android SDK on
first run.

```bash
# 1. Build the web app and copy it into the Android project
npm run cap:sync        # = next build && cap sync android

# 2. Open the native project in Android Studio
npm run cap:open        # = cap open android

# 3. Press ▶ Run in Android Studio (or build an APK)
```

Or, if you have the Android SDK + a device/emulator configured and `gradle`
available on your PATH:

```bash
npm run cap:run         # = next build && cap sync android && cap run android
```

Typical workflow after any web change: run `npm run cap:sync`, then Run again.

### How the floating bubble is implemented

- [`lib/floatingBubble.js`](lib/floatingBubble.js) — tiny JS bridge
  (`window.Capacitor.Plugins.FloatingBubble`); safe no-op on the web.
- [`android/.../FloatingBubblePlugin.java`](android/app/src/main/java/com/safetext/app/FloatingBubblePlugin.java)
  — Capacitor plugin: `hasPermission`, `requestPermission`, `show`, `hide`.
- [`android/.../FloatingBubbleService.java`](android/app/src/main/java/com/safetext/app/FloatingBubbleService.java)
  — foreground service that adds/removes the overlay bubble.
- [`android/.../MainActivity.java`](android/app/src/main/java/com/safetext/app/MainActivity.java)
  — registers the plugin.
- The UI toggle lives in [`app/SafeTextApp.js`](app/SafeTextApp.js) and only
  shows up when the app is actually running as the native Android app.

## Project structure

```
  manifest.webmanifest
  sw.js            # offline service worker
  icons/           # generated PWA icons
scripts/
  generate-icons.js
capacitor.config.json   # Capacitor config (appId, webDir: out)
android/                # native Android project (Capacitor + FloatingBubble)
```

## Deploying

It's a standard Next.js app configured for **static export**, so `npm run build`
generates the whole site into `out/`. Host that `out/` folder on any static host
(Netlify, GitHub Pages, S3, Vercel static, etc.). The same `out/` folder is what
Capacitor bundles into the Android app.
